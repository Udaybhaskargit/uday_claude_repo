# E3-S3 — Build the claim repository

**Epic:** E3 — Persistence Layer
**Layer:** Repository
**Group:** D
**Depends on:** E3-S1, E1-S2

## Description

Data-access layer for Claim, including creation, status mutation exclusively via the state-machine gate (E1-S2), and filtered listing for the document/fraud/assessor/admin queues.

## Acceptance Criteria

1. Given a new claim payload, when create() is called, then a row is inserted with status='INTAKE' and the generated id is returned.
2. Given an existing claim and a valid event from the E1-S2 transition table, when apply_transition() is called, then the row's status column is updated and a claim_state_transitions row is inserted in the same transaction.
3. Given an existing claim and an invalid event, when apply_transition() is called, then no row is mutated and InvalidClaimStateException propagates.
4. Given claims of mixed status and product, when list_by_status_and_product() is called with filters, then only matching rows are returned.
5. Given a policy_number and incident_date matching an existing non-void claim, when exists_duplicate() is called, then it returns True.
