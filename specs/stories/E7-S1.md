# E7-S1 — Implement the settlement service

**Epic:** E7 — Settlement & Reopen
**Layer:** Service
**Group:** I
**Depends on:** E6-S3, E3-S4

## Description

On an AUTO_APPROVE or manually approved decision, create an immutable payout Settlement record and invoke a stubbed payment trigger. This is AC-07.

## Acceptance Criteria

1. Given a decision outcome of AUTO_APPROVE, when settlement runs, then a Settlement row is created with the decision's payable_amount and the claim transitions to SETTLED.
2. Given a created Settlement row, when any code path attempts to modify it, then no update method exists, since the repository (E3-S4) enforces immutability.
3. Given settlement completes, when the stubbed payment trigger is invoked, then it returns a stub confirmation reference without contacting any real external payment rail.
4. Given a REJECTED claim, when settlement is attempted, then it is refused with a typed error and no Settlement row is created for a non-approved claim.
