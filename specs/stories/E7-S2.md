# E7-S2 — Implement the reopen/dispute service

**Epic:** E7 — Settlement & Reopen
**Layer:** Service
**Group:** E
**Depends on:** E3-S3, E1-S2

## Description

Allow a customer to dispute a SETTLED claim, creating a new linked sub-claim without mutating the original's terminal record, per AC-08 and NFR-02.

## Acceptance Criteria

1. Given a SETTLED claim, when reopen() is called, then a new Claim row is created with parent_claim_id set to the original's id and status='INTAKE'.
2. Given the reopen call succeeds, when the original claim is re-read, then its historical Decision, Settlement, and Assessment rows are unchanged: still readable, not deleted or edited.
3. Given the reopen call succeeds, when the original claim's status is re-read, then it is REOPENED, having been set via the state-machine gate rather than a direct column write.
4. Given a claim that is not SETTLED, for example one in MANUAL_REVIEW, when reopen() is called, then it raises InvalidClaimStateException.
