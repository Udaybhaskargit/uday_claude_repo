# E3-S4 — Build the append-only audit repositories

**Epic:** E3 — Persistence Layer
**Layer:** Repository
**Group:** D
**Depends on:** E3-S1

## Description

Data-access layer for the append-only entities FraudScreening, Assessment, Decision, Settlement, and AdminOverride, enforcing insert-only semantics (no UPDATE/DELETE exposed) to satisfy NFR-02.

## Acceptance Criteria

1. Given a FraudScreening record, when insert() is called twice for the same claim, then both rows persist with history preserved and no overwrite.
2. Given the repository module, when its public interface is inspected, then it exposes no update() or delete() method for any of the five entities.
3. Given a claim id, when get_latest_assessment() is called, then it returns the most recently inserted Assessment row for that claim.
4. Given a claim id, when list_admin_overrides() is called, then it returns all override rows ordered by timestamp ascending.
