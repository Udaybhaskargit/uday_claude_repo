# E1-S2 — Build the claim state machine transition gate

**Epic:** E1 — Domain Foundation
**Layer:** Types
**Group:** A
**Depends on:** (none)

## Description

Implement the centralized transition(claim, event) gate backed by a {FROM_STATE: {EVENT: TO_STATE}} table that is the only mechanism allowed to mutate Claim.status. This satisfies AC-10 and gives NFR-08 a mechanical target for a structural test (no service method may set claim.status directly).

## Acceptance Criteria

1. Given a claim in DOCS_PENDING and event DOCS_VERIFIED, when transition() is called, then the claim status becomes FRAUD_SCREENING.
2. Given a claim in SETTLED and event SUBMIT_FNOL (an invalid transition for that state), when transition() is called, then it raises InvalidClaimStateException and the claim status is unchanged.
3. Given the transition table, when every ClaimStatus value is checked, then each appears as a key with an explicit set of valid outgoing events and no implicit fallthrough.
4. Given a successful transition, when it completes, then a ClaimStateTransition record (from_state, to_state, event, timestamp) is returned for the caller to persist.
