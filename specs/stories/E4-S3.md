# E4-S3 — Detect and reject duplicate FNOL submissions

**Epic:** E4 — Claim Intake
**Layer:** Service
**Group:** F
**Depends on:** E4-S1, E3-S3

## Description

Reject a second FNOL for the same policy and incident date rather than silently creating a duplicate claim, while still allowing distinct incident dates on the same policy.

## Acceptance Criteria

1. Given an existing non-void claim for policy P on date D, when a second FNOL for (P, D) is submitted, then DuplicateClaimException is raised and no new Claim row is created.
2. Given an existing claim for policy P on date D1, when a new FNOL for (P, D2) with D2 not equal to D1 is submitted, then it succeeds and creates a second, independent claim.
3. Given DuplicateClaimException reaches the API layer, when serialized, then the HTTP response status is 409.
