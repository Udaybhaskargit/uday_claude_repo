# E10-S3 — Build the dispute action flow

**Epic:** E10 — Customer Portal
**Layer:** UI
**Group:** K
**Depends on:** E10-S2

## Description

Let a customer trigger the reopen flow (E9-S1 /reopen) from the tracker on a SETTLED claim, with a confirmation step.

## Acceptance Criteria

1. Given the Dispute this claim button on a SETTLED claim, when clicked, then a confirmation dialog appears before any API call is made.
2. Given confirmation, when the reopen API call succeeds, then the UI shows the new sub-claim id and a link to its tracker.
3. Given the reopen API call fails, for example with a 409 invalid state, when the error returns, then a user-facing error message is shown and the original claim's displayed status is unchanged.
