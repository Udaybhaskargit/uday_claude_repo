# E1-S1 — Define core domain types and enums

**Epic:** E1 — Domain Foundation
**Layer:** Types
**Group:** A
**Depends on:** (none)

## Description

Define the canonical domain model shared across all layers: Policy, Claim, ClaimDocument, FraudScreening, Assessment, Decision, Settlement, ClaimStateTransition, AdminOverride, and the Role/ClaimType/ClaimStatus enums. These types are the single source of truth referenced by config, repository, service, and API layers, per the Types to Config to Repository to Service to API to UI dependency chain (AC-01..AC-10 all reference these shapes).

## Acceptance Criteria

1. Given the Claim type definition, when inspected, then it exposes id, policy_id, claim_type (one of MOTOR|HEALTH|LIFE), incident_date, claim_amount (Decimal), status, and a nullable parent_claim_id.
2. Given the ClaimStatus enum, when enumerated, then it contains exactly INTAKE, DOCS_PENDING, FRAUD_SCREENING, ASSESSMENT, AUTO_APPROVED, MANUAL_REVIEW, REJECTED, SETTLED, REOPENED, PROCESSING_FAILED.
3. Given the Role enum, when enumerated, then it contains exactly CUSTOMER, ASSESSOR, ADMIN.
4. Given the Policy type, when inspected, then it exposes policy_number, product_type, status (ACTIVE|LAPSED|...), sum_insured (Decimal), effective_date, expiry_date.
5. Given any monetary field across Claim, Assessment, and Settlement, when its declared type is inspected, then it is a fixed-point Decimal type, never a floating-point float (NFR-01).
