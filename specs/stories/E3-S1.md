# E3-S1 — Write append-only numbered SQLite migrations

**Epic:** E3 — Persistence Layer
**Layer:** Repository
**Group:** C
**Depends on:** E2-S3

## Description

Write hand-rolled, numbered SQL migration scripts (migrations/0001_*.sql, 0002_*.sql, ...) that create tables for every entity in BRD section 9, applied in order at startup and never edited after being applied, per section 7.5.

## Acceptance Criteria

1. Given the migrations/ directory, when listed, then every file matches NNNN_description.sql and NNNN is strictly increasing with no gaps.
2. Given a fresh SQLite file, when the migration runner executes, then all 9 tables exist: policies, claims, claim_documents, fraud_screenings, assessments, decisions, settlements, claim_state_transitions, admin_overrides.
3. Given the migration runner, when run twice against the same database, then it is idempotent: already-applied migrations are skipped with no error.
4. Given an already-applied migration file, when its checksum is recomputed at startup, then a mismatch, indicating a post-application edit, raises a startup error.
