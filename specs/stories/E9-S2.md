# E9-S2 — Expose the document verification API

**Epic:** E9 — REST API
**Layer:** API
**Group:** G
**Depends on:** E5-S1, E8-S1

## Description

Expose endpoints for the internal document-verification queue to list pending checklist items and toggle VERIFIED/MISSING, wired to E5-S1.

## Acceptance Criteria

1. Given X-Role: ASSESSOR, when GET /api/claims/documents/pending is called, then the response lists only claims currently in DOCS_PENDING with their outstanding document types.
2. Given a claim's POLICE_FIR document, when PATCH /api/claims/{id}/documents/{type} sets it to VERIFIED, then the response reflects the update and, once all items are verified, a follow-up GET shows the claim's status as FRAUD_SCREENING.
3. Given X-Role: CUSTOMER, when the same PATCH endpoint is called, then the response is 403.
