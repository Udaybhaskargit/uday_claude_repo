# E2-S1 — Load fraud rule configuration from declarative config

**Epic:** E2 — Business Rule Configuration
**Layer:** Config
**Group:** B
**Depends on:** E1-S1

## Description

Load the fraud-scoring rule set (named rules, point weights, flag threshold) from a declarative JSON config file rather than hardcoding it in service logic, satisfying AC-04's determinism/configurability requirement.

## Acceptance Criteria

1. Given config/fraud-rules.json, when loaded at startup, then it contains exactly 5 rules matching BRD section 11 weights: ratio>0.8 (+40), filed within 3 days (+25), more than 2 claims in 90 days (+30), motor missing FIR (+15), round number divisible by 10000 (+10).
2. Given the loaded config, when the flag threshold is read, then its value is 60.
3. Given the config loader, when the file is missing or malformed, then it raises a typed config error at startup rather than the app starting with silent defaults.
4. Given the threshold value, when changed in the config file only with no code change, then the fraud service picks up the new value on next load.
