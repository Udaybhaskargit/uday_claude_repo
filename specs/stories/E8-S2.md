# E8-S2 — Implement the admin override service

**Epic:** E8 — Auth Boundary & Admin Override
**Layer:** Service
**Group:** E
**Depends on:** E3-S3, E1-S2, E8-S1

## Description

Allow an admin to force a claim decision or status with a mandatory reason code, recorded as an auditable, append-only AdminOverride event distinct from the automated decision trail. This is AC-09.

## Acceptance Criteria

1. Given an admin actor and a target claim, when override() is called with a command and reason code, then an AdminOverride row is inserted recording the admin actor, command, reason_code, and timestamp.
2. Given override() is called without a reason_code, when validated, then it raises a typed validation error and no override row is inserted.
3. Given an override that changes claim status, when applied, then the status change goes through the E1-S2 transition gate, and an invalid target status raises InvalidClaimStateException.
4. Given two admins concurrently overriding the same claim, when the second call runs against the now-stale state, then it fails with InvalidClaimStateException rather than silently double-applying, per BRD section 11 concurrency handling.
