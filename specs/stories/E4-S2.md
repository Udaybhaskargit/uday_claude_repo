# E4-S2 — Enforce policy-active validation at incident date

**Epic:** E4 — Claim Intake
**Layer:** Service
**Group:** F
**Depends on:** E4-S1, E3-S2

## Description

Before a claim proceeds past intake, validate the referenced policy is ACTIVE at the incident date, raising PolicyNotActiveException otherwise. This is AC-02.

## Acceptance Criteria

1. Given a policy with status='LAPSED', when submit_fnol() is called referencing it, then PolicyNotActiveException is raised and no Claim row is created.
2. Given an active policy but an incident_date after expiry_date, when submitted, then PolicyNotActiveException is raised.
3. Given an active policy with incident_date within [effective_date, expiry_date], when submitted, then no exception is raised and intake proceeds.
4. Given PolicyNotActiveException reaches the API layer, when serialized, then the response uses reason code POLICY_INACTIVE.
