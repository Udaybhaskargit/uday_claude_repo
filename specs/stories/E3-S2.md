# E3-S2 — Build the policy repository

**Epic:** E3 — Persistence Layer
**Layer:** Repository
**Group:** D
**Depends on:** E3-S1

## Description

Data-access layer for Policy: lookup by policy number and status-at-date check, used by the intake service to enforce AC-02.

## Acceptance Criteria

1. Given a seeded active policy, when get_by_number() is called, then it returns the Policy with matching sum_insured and dates.
2. Given a policy number that does not exist, when get_by_number() is called, then it returns None rather than raising, so the caller can produce a domain-level error.
3. Given a policy, when is_active_on(date) is called with a date outside [effective_date, expiry_date], then it returns False.
