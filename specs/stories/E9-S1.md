# E9-S1 — Expose the claims API for intake, tracking, and dispute

**Epic:** E9 — REST API
**Layer:** API
**Group:** I
**Depends on:** E4-S3, E6-S3, E7-S2

## Description

Expose POST /api/claims (FNOL), GET /api/claims/{id} (tracking), and POST /api/claims/{id}/reopen (dispute) for the Customer role, wired to the E4, E6, and E7 services.

## Acceptance Criteria

1. Given a valid motor FNOL body, when POST /api/claims is called with X-Role: CUSTOMER, then the response is 201 with a body containing the new claim_id and initial status.
2. Given a duplicate FNOL, when submitted, then the response is 409 with reason_code DUPLICATE_CLAIM.
3. Given a SETTLED claim id, when POST /api/claims/{id}/reopen is called, then the response is 201 with the new sub-claim's id and parent_claim_id.
4. Given GET /api/claims/{id} on an existing claim, when called, then the response body includes status, decision.reason_codes if decided, and a missing_documents list.
